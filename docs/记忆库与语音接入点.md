## 0.5 现在的记忆库（已上线，2026-11-07）

代码：`plugin/src/host/memory/store.ts`（唯一新增模块）+ `plugin/src/host/plugin/chat-memory.ts` 的 6 处接线。

### 三层，各管一件事

| 层 | 表 | 写什么 | 怎么用 |
| --- | --- | --- | --- |
| 原文层 | `messages` | 每一问一答，带 `ts` | 关键词命中后按时间衰减打分 |
| 事实层 | `memories` | 从用户话里抽的短结论（`她叫练志`/`我对花生过敏`/`她不喜欢香菜`） | 命中即置顶，权重 ×1.6 |
| 情绪 | 列 `valence/arousal/dominance/emotion` | 由 8 条词表规则给分（`affectOf`） | 情绪越强，半衰期越长：`30 × (1 + 0.9×|v|×a)` 天 |

三层都不改 scope、不改权限、不动原文。召回失败或库打不开时**整层降级为空实现**，对话照常进行。

### 一轮对话发生了什么

1. `chat-memory.ts:273` 首次对话把 `memory.json` 全量镜像进库（`syncTurns`，顺带补事实）。
2. `:277` `memoryDb.recall({ petId, query: text, limit: 6, before: oldestInWindow })` —— `before` 卡住最近几轮，避免和提示词里已有的历史重复。
3. `:278` `system = petSystemPrompt(...) + formatRecall(recalled)`，追加两段：

```
【关于她，你确定知道的事】以下几件事是她亲口说过的。只要话题相关，一律以这里为准：
- 我对花生过敏

【你想起的旧事】（更早的对话，按时间排序，只在贴题时提一句）
- 2026-11-05 她：我对花生过敏，你别给我点带花生的东西。
```

4. `:319` 回复写完后 `appendTurn` —— 同步写两条 `messages` + 抽事实写 `memories`。单条 insert 是微秒级，实测整轮 519–677 ms（不含额外阻塞）。

### 为什么用 LIKE 不用 FTS5（实测结论）

- `tokenize='unicode61'`：整句中文切成一个 token，搜「乳腺癌」0 命中。
- `tokenize='trigram'`：只支持 ≥3 字，「房东」「复查」「妈妈」全 0 命中。
- 现在按 2 字滑窗抽关键词 + `LIKE` 直扫，几千条是毫秒级。真到十万条再上向量（`bge-m3` + Float32 BLOB + 暴力余弦）。

### 抽事实的坑（踩过）

问句会被当成事实：「我对什么过敏？」抽出 `我对什么过敏`，下次真问过敏源时和自己的提问撞车，模型直接答「被问懵啦」。
现在 `looksInterrogative()` 把含 `什么/啥/哪/几/谁/多少/？` 的尾巴整条丢掉。

### 怎么验证

```bash

node --experimental-strip-types plugin/scripts/probe-memory.ts

# 端到端（要带调试端口启动）

```

`召回旧事 pet=main，1 条，最早 2026-11-05 → 事实:我对花生过敏`
（设 `DSH_PET_DEBUG_PROMPT=1` 还会打印 system 尾部，用来确认那一段真的拼进去了。）

### 回退与删除

- `memory.json` 仍是唯一真相：删掉 `memory.db*`，下次对话自动从 JSON 重建（实测 42 行全回来）。
- 想彻底关掉检索：删 `memory.db` 后把 `chat-memory.ts` 的 `recall` 那行注释掉即可，其余不动。

## 1. 记忆库：JSON → SQLite（当初的方案，已按 0.5 落地）

### 现在是这样的

`plugin/src/host/plugin/chat-memory.ts`

- `:54` `const memoryPath = join(userRoot, 'memory.json')`
- `:60` `readMemory()` / `:79` `writeMemory()` —— 整个文件读进来、整个写回去
- `:259` `const list = sliceMemoryRounds(entry.messages, rounds)` —— **只取尾部 N 轮**，`rounds` 来自 `conf.chatMemoryRounds`（缺省 5）
- `:262` `const system = petSystemPrompt(found, { historyTimes: list.length > 0 })`
- `:271` `generateChat({ ctx, system, history: list, userText: text, ... })`
- `:295` `await writeMemory(mem)` —— 把这一问一答追加进 JSON

也就是说：**模型能看到的过去 = 最近 5 轮**。再早的都在文件里，但从来没有被检索过。

### 要改成这样

只需要在 `:259` 和 `:262` 之间插一段「检索 → 拼块」，`:295` 之后加一段「异步落库」。`generateChat` 的入参形状不用动。

```ts
// chat-memory.ts 第 259 行之后
const list = sliceMemoryRounds(entry.messages, rounds);
const recalled = await recallMemories({ petId, query: text, limit: 6 }); // 新增模块
// ...
// 第 262 行：把检索结果接在人设后面
const base = petSystemPrompt(found, { historyTimes: list.length > 0 });
const system = recalled.length === 0 ? base : `${base}\n\n${renderRecalled(recalled)}`;
```

`renderRecalled` 按《情感记忆层设计》第 4 节的格式渲染，**只占 3–5 行**：

```
【你记得的】
- 她妈 2025-11 查出乳腺癌，做了手术（因为：你提过同一家医院）
- 她说闻到医院味道就心慌
- 她讨厌出差，主要是睡不好
```

**三个硬约束**（照抄文档里的底线，别在实现里松掉）：

1. 检索结果只影响「怎么提」，**不改 scope、不改权限、不动原文**。
2. 进提示词的一律 ≤6 条、总量 ≤500 字；超了就按分数截断，不做摘要。
3. 置信度 `confidence < 0.5` 的记忆不参与召回（宁可不提，也不要提错）。

### 落地顺序（别一次全上）

1. **先只加一张表 + 写入**：`messages` 已经在 JSON 里有了，先把它镜像进 SQLite（`memory.db`），检索还用老的 `sliceMemoryRounds`。跑一周，对比两份数据是否一致。
2. **再加 FTS5 召回**：`memories` 表 + `memories_fts` 虚表，中文要配 `tokenize='unicode61'`，否则中文分词为空。写入时用 `edge-tts` 同款思路：**异步、失败不影响回复**。
3. **最后加向量**：本地 embedding 直接调 Ollama，零新依赖：

   ```ts
   const r = await fetch('http://127.0.0.1:11434/api/embeddings', {
     method: 'POST',
     headers: { 'content-type': 'application/json' },
     body: JSON.stringify({ model: 'bge-m3', prompt: text }),
   });
   ```

   向量存 `BLOB`（Float32Array 的 `buffer`），暴力余弦就够——个人库几万条以内，SQLite 全表扫一遍是毫秒级，不用上向量数据库。

### SQLite 驱动怎么选

- **推荐 `node:sqlite`**（Node 22+ 内置，Electron 43 自带 Node 24 可用）。零依赖、零原生编译。
- 坑：`better-sqlite3` 需要 `electron-rebuild` 重编译原生模块，在 Windows 上还要装 VS Build Tools，**不建议**碰。
- 数据库放 `~/.dsh/dsh-pet/memory.db`，与 `memory.json` 同级；迁移期两个都写，出问题能回滚。

## 2. 语音：Edge TTS → Qwen3-TTS 克隆音色

### 现在是这样的

- 宿主侧实现：`plugin/src/host/voice/edge.ts:52` `synthesize({ text, voice, rate, target })` → 动态 `import('@andresaya/edge-tts')` → 写 `<target>.part` 再 `rename`。
- 注册表：`plugin/src/host/voice/registry.ts` —— 单槽，**后注册覆盖先注册**，返回一个 disposer：

  ```ts
  interface VoiceProvider {
    readonly id: string;
    readonly name: string;
    synthesize(input: { readonly text: string; readonly rate: string }): Promise<Uint8Array>;
  }
  registerVoiceProvider(def): () => void;
  ```

- 白名单音色：`plugin/src/host/voice/voices.ts`，四个中文音色，缺省 `zh-CN-XiaoyiNeural`（晓伊）。
- 客户端播放：`plugin/src/shared/voice.ts:228` `speak()` → `fetch(voiceBase + '/voice/speak')` → `response.blob()` → `new Audio(objectUrl)`。
- 缓存：`plugin/src/host/voice/cache.ts:19` 路径**写死 `.mp3`**，`:66` 淘汰只扫 `.mp3`。

### 要改成这样

写一个新文件 `plugin/src/host/voice/qwen.ts`，形状与 `edge.ts` 完全一样（同样写 `<target>.part` 再 rename），然后在注册处覆盖掉 edge：

```ts
// plugin/src/host/voice/qwen.ts 骨架
export async function synthesize({ text, voice, rate, target, signal }: SynthInput): Promise<void> {
  const staging = `${target}.part`;
  try {
    const res = await fetch('http://127.0.0.1:8000/tts', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ text, voice, rate, ref_wav: 'dafeiyu_ref.wav' }),
      signal,
    });
    if (!res.ok) throw new VoiceSynthError(`TTS ${res.status}`);
    await writeFile(staging, Buffer.from(await res.arrayBuffer())); // 必须是 mp3 字节
    await rename(staging, target);
  } catch (e) {
    await rm(staging, { force: true }).catch(() => undefined);
    throw new VoiceSynthError(e instanceof Error ? e.message : String(e));
  }
}
```

**必须返回 mp3 字节**：缓存文件名与淘汰逻辑都写死了 `.mp3`。Qwen3-TTS 输出 wav → 用 ffmpeg 转一道：

```
ffmpeg -i out.wav -codec:a libmp3lame -q:a 6 out.mp3
```

或者干脆让你的本地 TTS 服务端直接吐 mp3。

### 音色怎么定下来（重要）

Qwen3-TTS 的 **Voice Design** 模式（纯文字描述造音色）每次生成都略有不同，**不能每句话都现造**。正确做法：

1. Design 模式跑 10–20 次，挑一个满意的。
2. 导出成 `dafeiyu_ref.wav`（8–15 秒，干净无背景音）。
3. **之后全部走 Base 克隆模式**，参考音永远是这一个文件——音色才锁得死。

你后面自己录一段声音给我，也是同一个位置：把 `dafeiyu_ref.wav` 换成你的录音，代码一行不用改。

### 想立刻换成男声/别的腔调

改一行配置就行（`~/.dsh/dsh-pet/main-config.jsonc`）：

```jsonc
"voiceName": "zh-CN-YunxiNeural"   // 云希·男·年轻
```

四个可选：`zh-CN-XiaoxiaoNeural`（晓晓·女·通用）、`zh-CN-XiaoyiNeural`（晓伊·女·活泼）、`zh-CN-YunxiNeural`（云希·男）、`zh-CN-YunjianNeural`（云健·男·沉稳）。

## 3. 配置项速查（`~/.dsh/dsh-pet/main-config.jsonc`）

| 键 | 作用 | 现在 |
| --- | --- | --- |
| `voiceEnabled` | 语音播报总开关 | `true` |
| `voiceName` | 音色 id | `zh-CN-XiaoxiaoNeural` |
| `voiceVolume` | 音量 0–1 | `1` |
| `voiceWhisperEnabled` | 碎碎念也念出来 | `false`（每 5 分钟一句，会吵） |
| `voiceTodoEnabled` | 待办也念出来 | `false` |
| `pets[0].whisperEnabled` | 是否自说自话 | `true` |
| `pets[0].display` | 显示在桌面/网页/两端 | `both` |
| `animationWeights` | idle 90 / turn 0 / move 0 | 只有待机与小憩两条素材 |

模型与密钥**不在这里**，在 `~/.dsh/dsh-pet/standalone-ai.json`：

```jsonc
{
  "protocol": "openai-compatible",
  "baseUrl": "http://127.0.0.1:11434/v1",
  "model": "qwen3.5-unc:9b",
  "apiKey": "ollama",
  "maxTokens": 512,
  "timeoutMs": 60000,
  "reasoningEffort": "none"
}
```

两个会咬人的点：

1. **`timeoutMs` 上限 60000**，写 90000 会让整个应用起不来，报 `Cannot securely load standalone AI settings.`（这个异常同时覆盖「读盘失败」，别被误导）。
2. **思考型模型必须 `reasoningEffort: "none"`**。qwen3.5 默认把 token 全烧在 `reasoning` 上，`content` 回来是空的，表现为「碎碎念生成失败 reason=generate-error」。`think:false` 在 `/v1` 接口上无效，只有 `reasoning_effort` 有效。换成 DeepSeek/Claude 这类非思考模型时填 `""`。

## 4. 已经踩过并修好的坑（改代码前先读）

1. **`shared-core.js` 是构建产物**。`runtime/electron-helper/index.html:346` 引它，但它不在仓库里，必须跑 `node scripts/build-desktop-core.mjs`，否则渲染端从 `constants.js:72` 开始全崩（`Cannot read properties of undefined (reading 'translateRects')`）。
2. **`node_modules` 必须是 hoisted**。pnpm 的 junction 指向在本机 Node 24 上解析不了传递依赖，`tsdown` 会报 `Cannot find module 'debug'`。修法：`pnpm install --node-linker=hoisted`。
3. **`chat-panel` 入口不能进 tsdown 配置**。它把 react 内联，撞 rolldown 的 Windows 路径 bug（`Could not load C:Users\...\react\index.js`，盘符后反斜杠被吃掉）。`tsdown.pet.mjs` 只出 client / index / standalone / app 四份。
4. **改文件用 write/edit 工具，别用 PowerShell 的 `Get-Content -Raw | Set-Content`**，UTF-8 中文会被转成 GBK 乱码。
