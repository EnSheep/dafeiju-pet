# 本地 ComfyUI 批量做「大肥橘猫」桌宠动作素材 —— 可行性分析

> 结论先行：**能批量"生成候选"，不能批量"交付成品"**。ComfyUI 可以把成本从"每条人工抽卡"压到"GPU 小时"，但仓库要求的三条硬指标（10 秒 / 纯绿幕 / 首尾闭合）里，只有一条能被单次扩散模型满足。下面把每条约束、每个数字都落到你机器上的实测结果。

---

## 0. 一句话结论

| 问题 | 回答 |
| --- | --- |
| ComfyUI 能批量出这只猫的动作视频吗？ | 能。I2V + FLF2V + 脚本排队，108 条能无人值守跑完。 |
| 出来的能直接用进 dsh-pet 吗？ | 只有一部分。要先解决**白底→透明**和**时长/帧率**两件事，且需要人工挑片（经验废片率 30–50%）。 |
| 值不值得？ | 做 15–25 个"情绪动作"值得；做 108 个全量不值得，基础循环动作应该走图层/骨骼动画。 |
| 你现有素材合规吗？ | 规格合规（16:9 / 24fps / 10s），**背景不合规**（白底，不是绿幕）。 |

**关键冲突：白底 vs 绿幕。** `scripts/chroma_step02.py` 只把「色相 70°–170° + 饱和度 ≥0.15 + 明度 ≥0.15」的像素判成背景。你的白底（色相不确定、饱和度≈0）会被判成**非背景**，抠像后整帧不透明。而且角色本身有白围裙、白蕾丝、发丝高光，白色键控会把围裙一起吃掉。→ 你现在这条片子**不能走官方路线 A**，只能走路线 B（人工抠像）或者换方案（见 §5.3）。

## 2. 仓库的硬约束（逐条从脚本里抠出来的）

| 步骤 | 输入 | 输出 / 参数 |
| --- | --- | --- |
| `watermark_step01.py` | `video/*.mp4`（1280×720） | `step01/`，水印区用第 5 近背景色填充；mask 文件 `video/watermark_mask_v5.mkv`（仓库里已有，210 KB） |
| `chroma_step02.py` | `step01/` 1280×720@24 | `step02/*.webm`，libvpx-vp9 / yuva420p / CRF30，HSV 色相判定，色相边界 6° 羽化 |
| `normalize_step03.py` | `step02/` | `step03/`，画布 2160×1215，**站立高度 900 px**，脚底距底 100 px，按首尾站立帧的平均高度算缩放 |
| `encode_thumbs.py` | `step03/` | 640×360 播放变体 |
| 装机 | `dsh plugin --profile web add file:<插件目录>` | 资产进 `dsh-pet/assets/webm/` |

动画清单（`dsh-pet/assets/config.jsonc:283` 起）：idle 1 + turn 1 + drag 1 + clicks 5 + moves 3 + categories 约 98 = **109 条 webm**；睡觉是 `start/loop/end` 三段接力。

> 注意 `moves` 里有 `leadSec/tailSec`（首尾原地不动的秒数），说明**移动动画本身是不位移的走路循环**，位移由窗口完成。这正好和扩散模型"禁止 XY 位移"的提示词规则一致——对 ComfyUI 是利好。

## 3. ComfyUI 能做到什么 / 做不到什么

### 3.1 能做到（且有明确做法）

- **批量排队**：ComfyUI 有 HTTP API（`POST /prompt`、`GET /history/{id}`），workflow 是纯 JSON，可以做"模板 + 变量替换"，109 个动作循环提交，断点续跑逻辑照抄仓库 `_is_valid()` 的思路即可。
- **身份稳定**：I2V 用同一张无形变定妆图当首帧，跨片段的角色基本不变；同一 seed 家族 + 同一提示词骨架可进一步降漂移。
- **闭环循环**：**Wan2.1 FLF2V**（首尾帧控制）把"首帧"和"尾帧"都设成同一张图，就能得到数学上闭合的循环段——恰好对应 `睡觉-循环` 和所有 idle 循环。
- **抠像换成 matting**：BiRefNet / RMBG-2.0 / SAM2-video 节点直接出 alpha，"白底"不再是障碍，也不用绿幕。这一步直接绕过 `chroma_step02.py`，产出的只要是 1280×720@24 的透明 webm 就能进 `normalize_step03.py`。
- **无水印**：ComfyUI 出片没有平台水印，省掉 step01。

### 3.2 做不到 / 代价很高

| 约束 | 现实 | 数字 |
| --- | --- | --- |
| 10 秒 = 240 帧 @24fps 单次生成 | Wan2.1 I2V 81 帧@16fps = **5.06 s**；Wan2.2 TI2V-5B 121 帧@24fps = **5.04 s**；HunyuanVideo 129 帧 = **5.4 s**；CogVideoX 49 帧@8fps = 6 s；**只有 LTX-Video 能到 257 帧 ≈ 10.7 s**（13B dense，16 GB 上要 fp8 + 分块，慢） | 240 帧 vs 81–129 帧 |
| 纯 #00FF00 绿幕 | 扩散模型出不了均匀纯色：绿幕有噪点/渐变，角色边缘带绿色溢出（spill） | 必然需要 despill 或改走 matting |
| 帧间一致性 | 蕾丝、发丝、猫耳、尾巴环纹会轻微形变 + 闪烁；复杂动作（撸猫、玩魔方、变鸽子）出片率明显下降 | 经验废片率 30–50% |
| 物理合理性 | 手穿模、尾巴穿身体、服装抖动不自然 | 需要挑片 |
| 生成耗时（5070 Ti 16 GB） | Wan2.2 5B 720p 121 帧 ≈ 3–6 min/条；Wan2.1 14B fp8 480p 81 帧 ≈ 6–12 min/条；LTX distilled 5 s ≈ 1–3 min/条 | 108 条 × 2.5 次重试 ≈ **20–40 GPU 小时** |

## 4. 四条路线对比

| 路线 | 一致性 | 单条成本 | 108 条总量 | 门槛 | 适合 |
| --- | --- | --- | --- | --- | --- |
| A 云视频（豆包/可灵/Runway，你已在用） | 中 | 几分钟 + 抽卡 | 数十小时人工 | 低，但**要手动逐条抽**，且带水印 | 少量"英雄镜头" |
| B 本地 ComfyUI | 中低（需挑片） | 3–25 min GPU | 20–40 GPU 小时 + 30 GB 模型 | 中高（节点/显存/torch 版本） | 情绪动作、批量草稿 |
| C 图层/骨骼（Live2D / Spine / AE 拆层） | **100%（同一张图）** | 1–2 h/动作（一次性） | 10–12 个基础动作 ≈ 2–3 天 | 中（拆层 + 绑定） | 待机/睡觉/点击/走路等循环 |
| D 混合（推荐） | 高 | — | — | — | **C 打底 + B 补情绪 + A 补个别** |

**为什么推荐 C 打底**：桌宠 80% 的观看时间在"待机呼吸 / 睡觉 / 点击回应 / 走路"这四个循环上，它们对**循环闭合**和**身份稳定**的要求最高，而对"创新动作"要求最低——这正是骨骼动画的强项、视频扩散的弱项。视频扩散真正的价值在"一次性演出"类动作（吃、撸猫、被吓一跳、变魔术），这类只占清单的一部分。

## 5. 如果就走 ComfyUI：可执行方案

### 5.1 环境
1. ComfyUI 便携版（或 git + venv），**torch 必须 cu128+**（RTX 5070 Ti = sm_120）。
2. 模型（按性价比排序）：
   - `Wan2.2 TI2V-5B` fp8 —— 主力，720p/121 帧，16 GB 跑得动；
   - `Wan2.1 FLF2V-14B` GGUF Q6 + blockswap —— 只用来做**首尾同图**的闭环循环段；
   - `LTX-Video 0.9.x distilled` —— 需要单次较长（>6 s）时用；
   - `BiRefNet` 或 `RMBG-2.0` —— 抠像，替代绿幕；
   - 可选 `RIFE/FILM` 补帧（16 fps → 24 fps）。
3. 磁盘：至少预留 35 GB；只剩 54 GB 的话建议模型目录挪到别的盘（ComfyUI 支持 `extra_model_paths.yaml`）。

### 5.2 提示词改造
仓库的 `prompts/桌面宠物 10 秒动作提示词.md` 是给"能出 10 秒"的云端模型写的。喂给 5 秒模型要改三处：
- 删掉"10 秒"，改成"5 秒循环"；
- 动作幅度**降一档**（扩散模型的幅度普遍比提示词大，容易糊）；
- 保留全部硬约束：固定机位、无 XY 位移、首帧=参考站姿、首尾帧一致、纯色背景。

### 5.3 透明化两条路（选一条）
- **路 1（推荐）matting**：I2V 出白底/灰底视频 → BiRefNet 逐帧 alpha → 合成 1280×720@24 的 yuva420p webm（`-c:v libvpx-vp9 -pix_fmt yuva420p -crf 30 -auto-alt-ref 0`）→ 直接进 `normalize_step03.py`，跳过 step01/step02。
- **路 2 绿幕**：在 ComfyUI 里把背景约束成绿（提示词 + 后期把背景区替换成纯 #00FF00）→ 走官方 step01/02。缺点是角色边缘溢色，仍需 despill。

### 5.4 批量驱动骨架
```
for action in actions:                      # 109 条
    wf = template(action, seed=SEED[action], first_frame=reference_png)
    pid = POST /prompt(wf)
    wait GET /history(pid)
    save  video/<action>.mp4                 # 1280x720@24
# 之后：matting → step03 → step04 → assets/webm
```
验收（每条自动判、人只挑最终）：
- 首帧与定妆图 SSIM ≥ 0.90；
- 循环段首尾帧差 ≤ 阈值；
- alpha 边缘抖动率（相邻帧边缘位移）≤ 阈值；
- 时长/帧率/分辨率精确匹配。

## 8. 与"二次开发"目标的关系

你的设定是**猫娘女仆**（人类体型 + 猫耳 + 橘色条纹尾巴），而仓库那 109 条动画的原角色就是"Q 版女仆"——**骨架/动作库可以直接复用**，这是这次设定选择最大的隐藏收益：换成四脚猫的话，109 条提示词几乎全部要重写。

二次开发真正该改的是：`pet/<种类>-config.json`（新种类）、`whisperPrompt`（猫娘人格）、`memes`（表情包池）、以及视觉资产；插件代码本身（`src/host|client|shared`）大概率不用动。

# 附：能不能把官方 109 条视频"换角色"

## 9.1 先澄清一件事

仓库说的「换角色」= **换一套提示词/定妆图重新生成**（`MAKE-YOUR-OWN-PET.md:3` 只是口号），**没有** V2V 工具。官方 109 条片子（`F:\assets-videos\video`，109 个 mp4 / 186.4 MB / 每条 10 s / H.264 avc1）是**成品参考**，不是分层资产——所以"换角色"只能用 video-to-video 重新渲染，不是"替换贴图"。

## 9.2 四条路线

| 路线 | 做法 | 一致性 | 成本 | 主要失败点 |
| --- | --- | --- | --- | --- |
| **1 VACE 重绘** | Wan2.1 VACE R2V：官方片当控制视频 + 猫娘图当 reference | 中 | 14B ≈60–100 GPU h；1.3B ≈15–25 h | 81 帧上限要切 3 段拼接、跨段漂移、蕾丝/眼睛糊 |
| **2 关键帧重绘 + 光流传播** | 每条抽 5–10 张关键帧按定妆图重绘 → 光流传全片 | **高**（同一关键帧驱动） | 109×8≈900 张图，一夜跑完 | 快动作/遮挡拖影、细线条变软 |
| **3 只换外观层** | 蓝发→橘发调色 + 猫耳/尾巴贴图追踪叠加 | 100% | 几乎为零 | 脸和服装还是原角色，只算"同款换色" |
| **4 不换官方片，自己 I2V 重生成** | 用 `prompts/` 里 109 条提示词 + 你的定妆图 | 中高 | 同 §3（废片率 30–50%） | 5 s 上限、循环要 FLF2V |

**推荐：路线 2 为主 + 路线 1 兜底（补快动作）。** 理由：桌宠观感 90% 来自"运动对不对"，路线 2 的运动就是原片的运动（绝对对）；身份由重绘关键帧保证（绝对稳）；成本还最低。

## 9.3 一个关键工程技巧：保住绿幕

不要指望 V2V 重新生成出纯绿背景。正确做法是**分层**：

```
官方片 → chroma 提 alpha（背景/角色分离）
       → V2V 只重绘角色 RGB
       → 用原 alpha 把重绘结果合成回纯 #00FF00
       → 走 step02 / step03
```

好处：背景永远是纯绿（step02 必定能抠）、水印区在背景上（`watermark_mask_v5.mkv` 依然有效）、不用担心模型把背景画花。

## 9.4 必须先接受的质量预期

你的猫娘有**超大发量 + 一条粗尾巴**，而原片角色没有尾巴。控制信号（姿态/深度）里没有尾巴的信息，模型只能自由发挥 → **尾巴是最大失效点**（闪烁、穿模、时有时无）。缓解：尾巴单独做 2D 变形/骨骼叠加，或接受部分动作尾巴消失。

## 9.5 建议的最小验证

先挑 3 条最有代表性的跑路线 2：`待机呼吸休闲`、`点击回应-元气挥手`、`撸猫`。3 条约 2–4 小时。看完再决定要不要全量。
