# 大肥橘猫 · 桌面 AI 陪伴宠物

> 一只住在桌面上的 2D 猫。她记得你说过的话，会用你给她的音色回答你。
> 全部推理在本地完成，对话内容不出机器。

<img src="docs/assets/pet.png" width="320" alt="大肥橘猫">

<sub>↑ 待机动画的一帧。运行时是 60fps 的 webm 循环，带呼吸和眨眼。</sub>

---

## 这是什么

一个**能独立运行的 Windows 桌面宠物应用**（Electron），不是网页、不是聊天窗口套壳：

- 桌面上常驻一只透明置顶的二次元猫，待机呼吸、可以拖动、点击穿透
- 点开对话窗就能聊天，回复用**克隆音色**念出来
- **有长期记忆**：三层记忆库，记得住几天前说过的事、偏好和情绪
- 全程本地：聊天走 Ollama，语音走本地 Qwen3-TTS，记忆存 SQLite

它是 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet) 的一个 fork，
在原插件基础上做了三件原版没有的事：**独立成桌面应用**、**接上真正的记忆库**、**换上克隆音色**。

## 架构

```
┌─────────────────────── Electron 主进程 ────────────────────────┐
│  boot()                                                        │
│   ├─ 读 standalone-ai.json，建 OpenAI 客户端                     │
│   ├─ 造一个"假宿主"（插件需要的 ctx 极小子集）                     │
│   ├─ 起本机 HTTP 服务（127.0.0.1，随机端口，带 token 鉴权）        │
│   ├─ 挂载 dsh-pet 插件代码                                       │
│   └─ 拉起窗口栈（透明窗 / 托盘 / 动画 / 气泡）                     │
└───────────┬──────────────────────────────────┬─────────────────┘
            │ spawn                            │ BrowserWindow
            ▼                                  ▼
   ┌─────────────────┐               ┌──────────────────────┐
   │ tts_server.py   │◄── HTTP :8765 ─│ 渲染进程（宠物 + 气泡） │
   │ Qwen3-TTS 常驻   │               │ 长轮询 /state + <audio>│
   └─────────────────┘               └──────────────────────┘
            │
   ┌────────┴─────────┐
   ▼                  ▼
 Ollama :11434     memory.db (SQLite WAL)
 聊天 + 向量        memory.json（真相）
```

**一句话**：一个 Electron 进程里塞了三样东西——主进程、HTTP 服务、以及"假装自己是宿主"的适配层；
重活全在子进程或外部服务里。

## 快速开始

**先看 [REQUIREMENTS.md](REQUIREMENTS.md)**（硬件分档、显存账本、从零安装 7 步、故障对照表）。

最短路径：

```powershell
# 1. 启动 Ollama 并拉模型
ollama serve
ollama pull qwen3:14b
ollama pull bge-m3

# 2. 装依赖
cd plugin
npm install
npm run ensure:electron

# 3. 装 Python 环境（torch cu128 + qwen-tts，见 REQUIREMENTS 2.3）
# 4. 下 Qwen3-TTS 模型到 .qwen-tts\models\
# 5. 准备参考音色 wav + 逐字稿

# 6. 启动
双击 ..\启动桌宠.vbs
```

## 技术亮点（面试可讲的部分）

### 1. 记忆不是"塞进上下文"，是检索出来的

大模型无状态，所谓"记得你"其实是**每轮对话前检索相关旧事拼进 prompt**。

```
用户这句话
   ├─ ① 关键词路：中文两字滑窗 → SQL LIKE（FTS5 对中文不可用，实测 0 命中）
   ├─ ② 语义路：bge-m3 1024 维向量 → 暴力余弦（2000 条 1–3 ms）
   └─ ③ 事实路：抽取出的短结论优先占位
        ↓ 三路合流打分
   score = 3.2 × 余弦 × (0.4 + 时间衰减) + 加成
        ↓ 取 top 6（≤500 字）
   拼进 system prompt
```

**效果**：说「我最近不吃香菜了」，聊 6 轮无关的话之后问「我吃香菜吗」，
它仍然答得出来——这是 5 轮滑窗做不到的。

### 2. 遗忘曲线是有权重

```
保持率 = 0.5 ^ (经过天数 / 半衰期)
半衰期 = 30 天 × (1 + 0.9 × |情绪效价| × 情绪唤醒度)
```

情绪越强的记忆褪色越慢（最多延到 57 天）；而**事实层不衰减**——
"她对花生过敏"不该因为过了半年就不重要。

### 3. TTS 是硬瓶颈，用工程手段缓解

Qwen3-TTS 的 **RTF ≈ 1.8**（合成 10 秒话要 18 秒）。解决方案不是"假装流式"，是：

- 回复按句切片（标点切 + 超长再按逗号切）
- **第 N 片在播时预取第 N+1 片**（流水线）
- 片间停顿从 20 秒级降到 2–9 秒

诚实地说：这是缓解，不是解决。真解法要模型侧支持流式。

### 4. 平台级的坑（都能写进复盘）

| 坑 | 真因 |
|---|---|
| `Cannot find module 'debug'` | pnpm 的 junction，Node 24 的 `fs.realpathSync` **不解析 junction** |
| `Could not load C:Users\...\index.js` | rolldown 的 Windows 路径 bug，**盘符后的反斜杠被吃掉** |
| 回复是空字符串 | 思考型模型把 token 全烧在 `reasoning` 上，`think:false` 在 `/v1` 无效，只有 `reasoning_effort:'none'` 管用 |
| 启动后静默退出 | 单实例锁；`--user-data-dir` **绕不过**它 |

## 数据与隐私

- 所有对话、记忆、语音都在本地，**不出机器**（除非你主动把模型换成云端 API）
- `memory.json` 是唯一真相，`memory.db` 只是它的可检索索引，**删了会自动重建**
- 记忆可以一键清空：删掉这两个文件即可

## 声音克隆的边界

这套代码用你自己的录音克隆音色，请遵守：

- ✅ 克隆**自己的**声音
- ✅ 克隆**虚构角色**的声音
- ⚠️ 克隆**他人**声音需要对方明确同意（《民法典》第 1023 条：对自然人声音的保护参照肖像权）
- ❌ 不要用于伪造他人言论、电信诈骗

仓库里**不包含**任何人的参考音频样本。
